# 인스타그램 캡션 규칙

게시물 캡션과 해시태그를 만드는 규칙을 한곳에 모은 문서다. 캡션을 만드는 Claude 프롬프트와 코드는 이 문서를 따른다. 규칙을 바꾸려면 이 문서와 아래 "소스" 위치를 함께 고친다.

- 상태: 확정 (2026-11-15 사용자 점검)
- 설계: `docs/superpowers/specs/2026-11-14-review-to-instagram-design.md`
- 소스: `apps/api/src/main/java/com/kdrinker/caption/`
- 텔레그램 문구: `docs/telegram-messages.md`

## 캡션 틀

위에서 아래 순서다. 입력에 없는 내용이 필요한 블록은 통째로 뺀다. 내용을 지어 채우지 않는다.

```text
{첫 줄 훅}

{술 소개}

{맛·페어링}

{별점}

<!--brewery-->
{양조장 블록}
<!--brewery-->

{해시태그}
```

| 순서 | 블록        | 규칙                                                                                                                               |
| ---- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 첫 줄 훅    | 한 줄, 40자 안팎. 피드에서 "더 보기" 앞에 보이는 줄이다. 술 이름이나 메모의 핵심 한마디로 쓴다. 질문형이나 낚시 문구는 쓰지 않는다 |
| 2    | 술 소개     | 1~2문장. 이름, 종류(탁주 약주 청주 증류주 과실주 등), 도수, 용량 중 입력이나 라벨에서 확인된 것만 쓴다                             |
| 3    | 맛·페어링   | 1~3문장. 사용자 메모에서 나온 맛 표현과 함께 먹은 음식만 쓴다. 메모에 없으면 이 블록을 뺀다                                        |
| 4    | 별점        | `★4.5` 형식, 0.5 단위. 별점이 없으면 이 블록을 뺀다                                                                                |
| 5    | 양조장 블록 | 아래 "양조장 블록" 참고. 양조장을 못 찾았으면 마커 두 줄까지 포함해 비운다                                                         |
| 6    | 해시태그    | 마지막에 한 덩어리로, 공백으로 구분한다. 아래 "해시태그 규칙" 참고                                                                 |

블록 사이는 빈 줄 하나로 나눈다.

## 말투

- 사용자가 쓴 메모의 표현을 그대로 살린다. 사용자가 "달달하고 끝맛이 깔끔"이라고 썼으면 그 말을 쓰고, "풍부한 향의 조화" 같은 새 수식어로 바꾸지 않는다
- 과장 금지. "인생 막걸리", "최고의 한 잔", "꼭 마셔 보세요" 같은 단정과 권유를 쓰지 않는다. 사용자가 메모에 쓴 경우에만 쓴다
- 메모에 없는 맛, 향, 원료, 수상 이력, 역사, 효능을 지어 쓰지 않는다
- 평어체나 가벼운 해요체 하나로 통일한다. 기본은 해요체(`~했어요`, `~이에요`)
- 이모지는 양조장 블록의 항목 표시에만 쓴다. 본문에는 쓰지 않는다
- 느낌표는 쓰지 않는다. 긴 줄표 문자(엠 대시, 엔 대시)도 쓰지 않는다
- 광고처럼 읽히는 표현(협찬, 제공, 할인 안내)은 넣지 않는다

예시 (좋음 / 나쁨)

```text
좋음: 단맛이 먼저 오고 끝은 깔끔했어요. 전이랑 같이 마셨어요.
나쁨: 입안을 감싸는 풍성한 단맛의 향연! 어떤 안주와도 완벽한 조화를 이룹니다.
```

## 양조장 블록

캡션 안에서 양조장 부분만 따로 갈아 끼울 수 있도록 구분 마커 `<!--brewery-->`로 앞뒤를 감싼다. 마커 사이가 양조장 블록이다.

- 마커는 **내부 저장용**이다. DB에 저장하는 캡션에는 남기고, 인스타그램에 게시하기 직전에 제거한다. [상세]로 보여 주는 캡션 원문에서도 제거한 상태로 보여 준다
- 사용자가 캡션을 직접 고친 뒤 양조장이나 술을 바꾸면 캡션은 다시 만들지 않고, 마커 사이만 새 값으로 바꾼다
- 마커를 사용자가 지웠으면 양조장 블록 교체를 건너뛰고, 수정 화면에 마커가 없다는 안내를 보여 준다 (P8에서 구현)
- 시작과 끝에 같은 마커를 쓰는 것은 의도한 설계다. 캡션 안의 첫 번째 마커가 시작, 두 번째 마커가 끝이다. 마커가 정확히 2개가 아니면 사용자가 손댄 것으로 보고 위와 같이 교체를 건너뛴다
- 마커를 제거할 때 블록이 비어 있으면(양조장 미확인) 마커 줄과 함께 생기는 빈 줄도 정리해서, 앞뒤 블록 사이에 빈 줄이 하나만 남게 한다. 최종 캡션에는 빈 줄이 두 번 연속으로 나오지 않는다

양조장을 확인한 경우

```text
<!--brewery-->
🍶 {양조장 이름}
📍 {주소}
☎ {전화}
🏠 {홈페이지}
📷 @{인스타그램 핸들}
<!--brewery-->
```

예시

```text
<!--brewery-->
🍶 화요
📍 경기 여주시 가남읍 ...
☎ 031-...
🏠 hwayo.com
📷 @hwayo_official
<!--brewery-->
```

양조장을 못 찾은 경우 (블록을 비움)

```text
<!--brewery-->
<!--brewery-->
```

- 값이 없는 항목은 줄을 뺀다. 이름만 있으면 `🍶 {이름}` 한 줄만 남긴다
- 인스타그램 캡션의 링크는 눌러지지 않으므로 홈페이지는 `https://`를 뺀 주소 글자로 쓴다. 지도 링크는 캡션에 넣지 않는다 (텔레그램 개요에만 쓴다)
- 인스타그램 핸들은 `@`를 붙여 쓴다. 이 줄은 양조장에 노출되는 효과가 있어 확인된 핸들만 쓴다
- 양조장 블록 안의 값은 DB 또는 웹 검색 출처가 있는 값뿐이다. 출처 URL이 없는 웹 검색 결과는 분석 단계에서 버린다

## 해시태그 규칙

- 총 **12개 이하**. 인스타그램 한도(30개)보다 훨씬 적게 쓴다
- 구성 (위에서부터 채운다. 최대 6 + 1 + 1 + 1 + 1 + 2 = 12개)

| 구분      | 개수  | 예                                                                                   |
| --------- | ----- | ------------------------------------------------------------------------------------ |
| 고정 태그 | 6개   | `#전통주` `#우리술` `#전통주후기` `#막걸리` `#전통주추천` `#막걸리추천`              |
| 술 종류   | 0~1개 | `#약주` `#청주` `#증류주` `#과실주` (막걸리는 고정 태그에 있으므로 따로 넣지 않는다) |
| 술 이름   | 1개   | `#화요25` (공백 없이 붙임)                                                           |
| 지역      | 0~1개 | `#여주` (양조장 주소의 시군구, 없으면 시도)                                          |
| 양조장    | 0~1개 | `#화요` (양조장 이름, 법인 표기 제외)                                                |
| 페어링·맛 | 0~2개 | `#전과막걸리` (메모에 나온 것만)                                                     |

- 고정 태그는 2026-11-15 사용자 점검에서 확정했다. 술 종류와 상관없이 모든 게시물에 붙는다
- 같은 태그를 두 번 쓰지 않는다. 띄어쓰기, 특수문자(`.` `-` 등)를 지우고 붙여 쓴다
- 양조장을 못 찾았으면 지역과 양조장 태그는 뺀다
- 태그를 지어 채워서 개수를 맞추지 않는다. 12개보다 적어도 된다
- 삭제 우선순위(줄여야 할 때): 페어링·맛, 지역, 양조장 순으로 뺀다. 고정 태그와 술 이름은 마지막까지 남긴다

## 2,200자 상한

인스타그램 캡션은 최대 2,200자다. 세는 기준은 마커를 제거한 최종 캡션(해시태그 포함)의 글자 수(유니코드 코드 포인트)다. 이모지는 한 글자로 센다.

| 상황                                     | 처리                                                                                                                                                                                                     |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 생성한 캡션이 2,200자 이하               | 그대로 쓴다. 텔레그램 개요에 글자 수를 표시한다                                                                                                                                                          |
| 생성한 캡션이 2,200자 초과               | 글자 수를 코드로 세어 확인한 뒤, Claude에게 줄여 달라고 한 번 더 요청한다. 줄일 때는 맛·페어링과 술 소개를 줄이고, 양조장 블록과 별점은 건드리지 않는다. 사용자 메모에서 가져온 표현은 마지막까지 남긴다 |
| 다시 요청해도 초과                       | 해시태그를 우선순위대로 줄이고, 그래도 넘으면 맛·페어링 블록을 뒤에서부터 자른다. 문장 중간에서 끊지 않는다. 글자 수는 항상 코드로 확인하고 Claude의 계산을 믿지 않는다                                  |
| 사용자가 수정 화면에서 고쳐 2,200자 초과 | 수정 화면에서 저장을 막고 글자 수를 보여 준다 (P8에서 구현)                                                                                                                                              |
| 게시 직전 검증                           | 초과면 PUBLISHING으로 가지 않고 FAILED로 둔다. 텔레그램 실패 알림(메시지 9)의 사유는 `캡션이 2,200자를 넘었습니다.`이고, 재시도로는 해결되지 않으므로 [수정] 버튼만 붙인다                               |

- 글자 수는 보통 600자 안팎이라 초과는 드문 경우다. 그래도 게시 직전에 한 번 더 검사한다

## Claude 프롬프트 요지

캡션 생성 단계의 프롬프트(P2에서 구현)가 담아야 할 내용이다. 세부 문장은 구현 때 정하되, 아래 규칙은 이 문서와 같아야 한다.

**입력**

- 라벨 인식·메모 구조화 결과: 술 이름, 종류, 도수, 용량, 별점, 맛 노트, 페어링, 원본 메모
- 양조장: 확인된 값만(이름, 주소, 전화, 홈페이지, 인스타그램 핸들). 못 찾았으면 "없음"
- 설정값: 고정 해시태그 목록, 해시태그 상한(12), 글자 수 상한(2,200)

**지시**

1. 위 "캡션 틀"의 순서와 빈 줄 규칙을 따른다. 입력에 없는 블록은 통째로 뺀다
2. 사용자 메모의 표현을 그대로 살린다. 새 수식어, 과장, 권유 문구를 쓰지 않는다
3. 입력에 없는 사실(맛, 원료, 수상, 역사, 양조장 정보)을 지어 쓰지 않는다. 모르면 쓰지 않는다
4. 느낌표와 긴 줄표 문자를 쓰지 않는다. 본문에 이모지를 쓰지 않는다
5. 양조장 블록은 `<!--brewery-->` 마커로 감싸서, 양조장 입력이 없으면 비운 채로 출력한다
6. 해시태그는 규칙표의 구성과 12개 상한을 따른다
7. 전체가 2,200자를 넘지 않게 쓴다

**출력** (structured output)

| 필드       | 설명                                |
| ---------- | ----------------------------------- |
| `hook`     | 첫 줄 훅                            |
| `intro`    | 술 소개                             |
| `tasting`  | 맛·페어링 (없으면 빈 문자열)        |
| `hashtags` | 해시태그 배열 (`#` 포함, 중복 없음) |

- 캡션 조립(블록 순서, 별점 줄, 양조장 블록, 마커)은 코드가 한다. Claude는 문장과 태그만 만든다. 그래서 양조장 값이 Claude의 문장에 섞여 틀어지는 일이 없다
- 글자 수 검사, 해시태그 개수 검사, 마커 삽입과 제거도 코드가 한다
