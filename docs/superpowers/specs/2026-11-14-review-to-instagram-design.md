# 전통주 후기 → 인스타그램 자동 게시 설계

- 날짜: 2026-11-14
- 상태: 승인됨
- 선행: `2026-11-13-init-setup-design.md` (web·api 뼈대, `ApiResponse`·`ErrorCode`·`apiFetch`)

## 의도

전통주를 마시는 자리에서 휴대폰으로 사진 몇 장과 짧은 메모만 보내면, 양조장 정보가 붙은 인스타그램 게시물이 만들어지고, 텔레그램에서 버튼 한 번으로 게시되게 한다. 사용자 한 명(본인)의 인스타그램 계정을 전통주 인플루언서 계정으로 키우는 데 드는 반복 작업(술 이름·양조장 찾기, 캡션·해시태그 작성, 업로드)을 없애는 것이 목적이다.

## 목표

1. **입력 두 경로**: (A) 텔레그램 봇에 사진 + 메모 전송, (B) 안드로이드 갤러리 "공유" → k-drinker(PWA) 입력 화면. 둘 다 같은 처리 흐름으로 들어간다.
2. **자동 분석**: 라벨 사진에서 술 이름 인식, 메모에서 별점·맛·페어링 정리, 양조장 자동 매칭(주소·전화·홈페이지·SNS 계정), 캡션·해시태그 생성.
3. **텔레그램 확인 후 게시**: 개요 메시지(양조장 링크 포함)와 [확인] [상세] [수정] [취소] 버튼. [확인]을 누르면 인스타그램에 게시하고 완료 알림을 보낸다.
4. **웹**: 로그인, 공유 입력 화면, 게시물 수정 화면, 지난 기록, 양조장 정보 관리.

## 비목표

- 블로그(네이버·티스토리) 게시. 공식 글쓰기 API가 없어 이번 범위에서 뺀다.
- 여러 사용자 가입, 계정별 SNS 연동.
- 아이폰 지원(iOS 단축어 등). 사용자는 안드로이드만 쓴다.
- 릴스·영상 게시.
- "홍보 기능 추천" 항목들. 체크한 항목만 본 기능 이후 별도 설계로 진행한다.

## 실패로 보는 것 (안티 목표)

- 틀린 양조장 주소·전화번호·계정이 확인 없이 공개되는 것. 그래서 모든 게시는 텔레그램 [확인]을 거친다.
- 같은 게시물이 두 번 올라가는 것 ([확인] 연타, 재시도).
- 입력이 웹으로 사진을 올리고 폼을 채우는 것보다 번거로워지는 것.

## 제약

- 스택·배포는 lottery-picker와 같다: Next.js 16 / React 19 / Tailwind 4 / pnpm, Spring Boot 4.1 / Java 17 / JPA / Flyway, MySQL 8.4, Synology NAS Docker Compose, GHCR, DSM 역방향 프록시 HTTPS. 텔레그램은 lottery-picker의 롱 폴링(`getUpdates`) 방식, 웹 로그인은 lottery-picker의 TOTP 방식을 가져온다.
- 도메인 로직(분석·매칭·캡션·게시)은 모두 `apps/api`에 둔다. 웹은 호출하고 표시만 한다.
- **인스타그램**: Instagram API with Facebook Login(통합 로그인, `graph.facebook.com`)으로 게시한다. 계정은 프로페셔널(크리에이터) 계정이어야 한다.
  - 변경 (2026-11-17): 처음에는 Instagram Login(`graph.instagram.com`)으로 설계했으나, 최신 Meta 앱에서는 그 방식을 쓸 수 없어 통합 로그인으로 바꿨다. Facebook 페이지는 여전히 필요 없다.
  - 캐러셀은 최대 10장, 캡션은 최대 2,200자, 이미지는 JPEG, 8MB 이하, 비율 4:5~1.91:1이다. 캐러셀의 모든 장은 첫 장 비율로 잘린다.
  - 이미지는 Meta 서버가 가져갈 수 있도록 **공개 HTTPS URL**에 있어야 한다.
  - 하루 게시 한도는 50건 또는 100건이다(문서마다 다르다). 개인 사용이라 문제가 되지 않는다.
  - 토큰은 통합 로그인 구성의 시스템 사용자 토큰으로, 만료되지 않아 갱신하지 않는다. 확인한 게시 한도는 24시간 100건이다.
  - 수치는 구현 시점에 Meta 공식 문서로 다시 확인한다.
- **Claude API**: Java SDK(`com.anthropic`), 모델 `claude-opus-5-5`. 거부 응답에 대비해 server-side fallback(`fallbacks: "default"`)을 켠다. 라벨 인식은 이미지 입력, 결과 구조화는 structured outputs, 양조장 보강은 `web_search_20260209`를 쓴다.
- **텔레그램 봇**: 파일 다운로드는 20MB까지다. 사진으로 보내면 텔레그램이 긴 변을 1280px 정도로 압축하는데, 인스타그램 게시(가로 1080px)에는 충분하다. 앨범은 메시지 여러 개가 같은 `media_group_id`로 들어온다.
- 환경변수를 추가하면 `application.yml`, `apps/api/.env.example`, `deploy/.env.example`, `deploy/compose.yml`, `deploy/README.md`를 함께 고친다. 응답 포맷은 `api-conventions` 스킬을 따른다.

## 접근 방식

### 양조장 매칭

| 방식 | 장단점 | 선택 |
|---|---|---|
| **A. 공공 데이터 DB 우선 + Claude 웹 검색으로 보강** | 주소·전화가 공식 출처라 정확하다. 한 번 확인한 양조장은 비용 없이 재사용된다. 처음 데이터를 적재하는 작업이 필요하다. | ✓ |
| B. 매번 Claude 웹 검색 | 가장 단순하지만 비용이 들고 지어낸 정보가 섞일 위험이 있다. | ✗ |
| C. 직접 입력 + 자동완성 | 정확하지만 "자동 매칭"이라는 목적에 맞지 않는다. | ✗ |

### 게시 전 확인

| 방식 | 선택 |
|---|---|
| 웹 미리보기 화면에서 확인 | ✗ |
| 확인 없이 자동 게시 | ✗ (틀린 정보 공개 위험) |
| **텔레그램 개요 + [확인] [상세] [수정] [취소]** | ✓ (사용자 결정) |

### 입력 경로

| 방식 | 선택 |
|---|---|
| **A. 텔레그램 봇에 사진 + 메모** | ✓ |
| **B. 안드로이드 공유 → PWA(Web Share Target)** | ✓ |
| C. 웹 입력 폼만 | ✗ (매번 웹을 열어야 함) |
| iOS 단축어 | ✗ (안드로이드만 사용) |

## 동작

### 전체 흐름

```
[A] 텔레그램: 사진(앨범) + 메모 ──┐
[B] 갤러리 공유 → PWA 입력 화면 ──┤
                                  ▼
               api: 게시물 접수 (RECEIVED) — 사진 저장, 즉시 "접수됨" 응답
                                  ▼  (비동기)
               분석 (ANALYZING)
                 1. Claude: 라벨 사진 + 메모 → 술 이름·별점·맛·페어링 (structured output)
                 2. 양조장 매칭: DB 검색 → 없거나 빈 칸이면 Claude 웹 검색(출처 URL 필수)
                 3. 사진 변환(비율·크기·JPEG) → 공개 URL
                 4. Claude: 캡션 + 해시태그 생성
                                  ▼
               검토 대기 (PENDING_REVIEW) — 텔레그램 개요 + [확인][상세][수정][취소]
                 ├ [상세] → 사진 앨범 + 캡션 원문 전송 (상태 그대로)
                 ├ [수정] → 웹 수정 화면 링크 → 저장 → 새 개요 재전송 (이전 메시지 버튼 제거)
                 ├ [취소] → CANCELED, 버튼 제거
                 └ [확인] → PUBLISHING → 인스타그램 게시
                                  ▼
               PUBLISHED — 완료 알림(게시물 링크) / FAILED — 실패 사유 + [재시도]
```

- 분석에 실패하면(라벨 인식 실패, Claude 오류) FAILED로 두고 텔레그램으로 알린다. 알림에는 [재시도]와 [수정]을 붙인다. [재시도]를 누르면 실패한 단계부터 다시 실행한다(분석 실패면 ANALYZING, 게시 실패면 PUBLISHING). [수정]으로 저장하면 PENDING_REVIEW로 가고 새 개요를 보낸다.

### [수정] 범위 (설계자 결정)

- 고칠 수 있는 것: 술 이름(기존 `Drink` 검색·선택 또는 새로 입력), 양조장(기존 선택 또는 필드 수정), 별점, 메모, 캡션·해시태그, 사진 순서와 삭제.
- 양조장 필드를 고치면 공유 `Brewery` 레코드에 바로 반영한다(`source=MANUAL`, `verified=true`). 앞에서 정한 "다음 글부터 맞게 붙도록"이 이 동작이다. 이미 게시된 글의 캡션은 게시 시점의 텍스트라 바뀌지 않는다.
- 술이나 양조장을 바꾸면 캡션을 다시 생성한다. 단, 사용자가 캡션을 직접 고친 경우에는 다시 생성하지 않고, 양조장 블록만 새 값으로 바꾼다. 양조장 블록은 캡션 안에서 템플릿으로 구분해 둔다.
- 저장하면 PENDING_REVIEW로 바꾸고 버전을 올린 뒤, 새 개요를 보낸다.
- 양조장을 못 찾아도 개요는 보낸다. 대신 "⚠ 양조장 미확인"을 맨 위에 표시하고, 캡션의 양조장 블록은 비운다.
- [확인]은 상태가 PENDING_REVIEW일 때만 받는다. 연타는 상태 전이로 막는다(조건부 UPDATE). 오래된 개요 메시지의 버튼은 게시물 버전을 함께 실어 무시한다.
- [확인]을 누르면, 개요에 보였던 양조장 정보는 `verified=true`로 저장한다. 사용자가 본 정보이므로 다음 매칭부터 웹 검색 없이 쓴다.

### 텔레그램 개요 메시지 (형태 예시, 실제 문구는 T1에서 확정)

```
🍶 게시 대기 · 화요 25 (★4.5)
양조장: 화요 (출처: 공공데이터)
📍 경기 여주시 가남읍 ...   ← 지도 링크
🏠 홈페이지   📷 @hwayo_official   ☎ 031-...
사진 3장 · 캡션 412자 · 해시태그 15개
[확인] [상세] [수정] [취소]
```

웹 검색으로 채운 항목에는 출처 링크를 함께 붙인다.

### 입력 해석

- **텔레그램**: 같은 `media_group_id` 메시지를 마지막 수신 후 3초 동안 모아 하나의 게시물로 만든다. 메모는 앨범 캡션이나 그 직후 텍스트 메시지다. 사진 없이 텍스트만 오면 안내 메시지를 보낸다.
- **공유(B)**: `manifest`의 `share_target`(POST, multipart, `image/*`)으로 받는다. 입력 화면은 사진 미리보기, 별점(0.5 단위), 한 줄 메모, [보내기]로 구성한다. 보내면 같은 접수 API를 호출한다. 로그인이 안 되어 있으면 로그인 후 공유한 사진을 그대로 이어서 처리한다.
- 별점은 메모에서 숫자(예: `4.5`)를 찾고, 없으면 비워 둔 채 개요에 "별점 없음"으로 표시한다. 별점 없이 게시하는 것은 허용한다.
- **사진 비율 (사용자 결정)**: 모든 장을 4:5로 통일하고, 술병 위치를 중심으로 자동으로 자른다. 라벨 인식을 호출할 때 Claude가 사진마다 술병 영역(비율 좌표)도 함께 돌려준다. 술병을 못 찾은 사진은 가운데를 기준으로 자른다. [상세]에서는 잘린 결과를 보내 준다. [수정] 화면에서는 사진마다 "여백 넣기"(4:5 틀 안에 원본을 넣고 흐린 배경으로 채움)로 바꿀 수 있다. 직접 자르는 기능은 만들지 않는다.
- 첫 번째 사진을 라벨 사진으로 가정하지 않는다. 모든 사진을 Claude에 넘겨 라벨이 보이는 사진을 고르게 한다. 게시 순서는 보낸 순서를 따른다.

### 보안·인증

- 텔레그램은 설정된 본인 `chat_id`에서 온 메시지와 버튼만 처리한다. 나머지는 무시한다.
- 웹은 TOTP 로그인 세션으로 보호한다(lottery-picker 방식). 본인 휴대폰 전용이므로 세션은 90일 동안 유지한다(설계자 결정, 공유할 때마다 TOTP를 입력하지 않게). 로그인이 풀린 상태에서 공유하면 사진을 보관하지 않고, "로그인 후 다시 공유해 주세요" 화면을 띄운다. 인증 없는 업로드 경로는 만들지 않는다.
- 인스타그램 토큰(설계자 결정, 2026-11-17 변경): 사용자가 Meta 대시보드에서 만료 없는 시스템 사용자 토큰을 발급해 `INSTAGRAM_ACCESS_TOKEN`으로 넣는다. API는 DB에 토큰이 없을 때만 이 값으로 초기화하고, 갱신하지 않는다. 토큰이 무효가 되면 게시 실패(인증) 알림으로 드러나고, 재발급 절차는 `deploy/README.md`에 있다. 재발급한 토큰은 환경변수를 바꾸고 웹 설정 화면에서 [토큰 다시 불러오기]를 눌러 반영한다. OAuth 콜백은 만들지 않는다.
- 공개 이미지 URL은 `/api/v1/media/{추측 불가 토큰}.jpg` 형태로, 인증 없이 열린다. 게시 후에도 남긴다(인스타그램이 이미 복사함). 취소된 게시물의 이미지는 7일 후 지운다.
- Anthropic, Instagram, Telegram 키·토큰은 환경변수로 둔다. 인스타그램 토큰은 [토큰 다시 불러오기]로 바꿀 수 있게 DB에 저장한다.

## 데이터 (초안)

| 엔티티 | 주요 필드 |
|---|---|
| `Brewery` | 이름, 주소, 전화, 홈페이지, 인스타그램 핸들, 기타 SNS, 출처(`PUBLIC_DATA`/`WEB_SEARCH`/`MANUAL`), 출처 URL, `verified` |
| `Drink` | 이름, 별칭, 종류(탁주·약주·청주·증류주·과실주 등), 도수, 용량, `brewery_id` |
| `Post` | `drink_id`, 별점, 원본 메모, 맛 노트, 페어링, 캡션, 해시태그, 상태, 버전, 입력 경로(`TELEGRAM`/`SHARE`), 텔레그램 메시지 id, IG 미디어 id, permalink, 실패 사유, 시각들 |
| `PostPhoto` | `post_id`, 순서, 원본 경로, 변환본 경로, 공개 토큰, 술병 영역(비율 좌표, 없으면 null), 맞춤 방식(`CROP`/`PAD`) |
| `InstagramToken` | 토큰, 만료 시각, 마지막 갱신 |

상태: `RECEIVED → ANALYZING → PENDING_REVIEW → PUBLISHING → PUBLISHED`. 어느 단계에서든 `FAILED`로 갈 수 있고, `PENDING_REVIEW`에서 `CANCELED`로 갈 수 있다. `FAILED`에서 [재시도]를 누르면 실패한 단계(`ANALYZING` 또는 `PUBLISHING`)로 돌아가고, [수정] 후 저장하면 `PENDING_REVIEW`로 간다. `Post`에는 실패한 단계를 함께 저장한다.

## 홍보 기능 추천 (선택)

넣을 항목은 `[ ]`를 `[x]`로 바꿔 표시한다. 체크한 항목만 본 기능(T0~T9)이 끝난 뒤 별도 설계·계획으로 진행하고, 체크하지 않은 항목은 범위 밖으로 둔다. 순서는 효과 대비 비용 순이다.

- [ ] **양조장 계정 태그·협업 게시**: 게시물에 양조장 인스타그램 계정을 사진 태그하거나 협업자(collaborator)로 초대한다. 양조장이 리그램하거나 공유할 가능성이 커서 노출 효과가 가장 크다. 이미 매칭한 핸들을 그대로 쓰므로 비용도 적다. API 지원 범위는 확인이 필요하다.
- [ ] **주간 성과 리포트 (텔레그램)**: Instagram Insights로 게시물별 도달, 저장, 공유, 팔로워 증감을 매주 요약해 보낸다. 어떤 술, 어떤 사진 구성이 반응이 좋은지 보인다.
- [ ] **게시 시간 예약**: 개요에서 [확인] 대신 [저녁 8시에 게시]를 고를 수 있게 한다. 반응이 좋은 시간대에 게시하는 데 쓴다. 2번 데이터가 쌓이면 추천 시간도 제안할 수 있다.
- [ ] **첫 장 정보 카드 이미지**: 술 이름, 양조장, 도수, 원료, 별점, 페어링을 담은 카드 이미지를 자동으로 만들어 캐러셀 첫 장이나 마지막 장에 넣는다. 저장 수를 늘리는 데 효과적인 형식이다.
- [ ] **공개 아카이브·전통주 지도 페이지**: 지금까지 마신 술을 지역별 지도와 목록으로 보여 주는 공개 웹페이지다. 프로필 링크로 쓰고, 양조장이나 브랜드에 보내는 협찬 제안용 포트폴리오(미디어킷)로도 활용한다.
- [ ] **댓글·DM 알림과 답글 초안**: 새 댓글을 텔레그램으로 알리고, Claude가 답글 초안을 만든다. [보내기] 버튼으로 바로 답할 수 있다. 소통 빈도가 계정 성장에 영향을 준다.
- [ ] **시리즈 기획 보조**: "이번 달 막걸리 10선", "지역 양조장 투어"처럼 기록을 묶은 기획 게시물 초안을 만든다.
- [ ] **협찬·체험 문의 관리**: 들어온 제안을 기록하고, 협찬 게시물에는 "유료 광고 포함" 표시를 자동으로 넣는다.

## 빌더 재량

- 비동기 실행 방식(`@Async`, 작업 테이블 폴링 등), 사진 변환 라이브러리, 앨범 묶기 대기 시간의 세부 값.
- Claude 호출을 몇 번으로 나눌지(분석과 캡션을 합칠지), 프롬프트 세부. 단, 캡션 말투와 규칙은 T1 문서를 따른다.
- 웹 화면 디자인. 휴대폰 화면 우선, 최소한으로.
- 텔레그램 봇은 lottery-picker와 다른 **새 봇**을 쓴다 (설계자 결정, 알림이 섞이지 않게).
- 맛 노트 항목(단맛·산미·바디·탄산·향 등)은 메모에서 나온 것만 채운다. 별도 입력란은 만들지 않는다 (설계자 결정, 입력을 간단하게 유지).
