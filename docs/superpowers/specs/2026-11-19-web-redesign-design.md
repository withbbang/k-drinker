# 웹 리디자인과 수정 화면 사용 방식 개선 설계

- 날짜: 2026-11-19
- 상태: 초안 (사용자 검토 대기)
- 선행: `2026-11-18-web-channel-design.md`, `2026-11-18-photo-edit-undo-design.md`
- 계기: 실기기 사용 피드백. 디자인이 투박하고, 수정 화면이 익숙한 앱 사용 방식과 맞지 않는 곳이 많다 (양조장·술 검색, 사진 이동, 사진 버튼, 되돌리기 등). 사용자가 하나하나 짚지 못할 만큼 많다고 했다.

## 의도

웹 전체에 전통주다운 일관된 겉모양을 입히고, 수정·공유 화면이 인스타그램·카카오·배달앱·구글 포토 같은 앱을 쓰던 손버릇대로 동작하게 한다. 이 웹은 TOTP 로그인을 거쳐 사용자 한 명만 쓰는 관리 도구다. 보여 주기용 화려함보다 휴대폰에서 빠르고 예측 가능하게 쓰이는 것이 우선이다.

화면 손질을 하다 보니 사용 방식이 어긋나는 뿌리가 데이터 흐름에도 있었다. 양조장 정보를 게시물 수정 화면에서 고치면 다른 게시물까지 바뀌고, 술을 바꾸면 저장할 때 Claude가 캡션(인스타그램 글)을 통째로 다시 써서 화면에 보이던 글과 올라갈 글이 달라졌다. 이 설계는 둘 다 고친다.

## 목표

1. 양조장 정보는 수정 화면 위 **양조장 시트**에서 고치고 바로 저장한다. 고친 값은 아직 게시하지 않은 게시물의 캡션에 반영된다.
2. 웹에서 검토하게 된 게시물은 텔레그램 버튼을 지우고 **안내 메시지**를 보낸다.
3. 캡션은 Claude가 **처음 한 번만** 쓴다. 사실 정보는 **이름표**(`{술이름}` 등)로 저장하고 보여 줄 때·게시할 때 서버가 채운다. 술·양조장·별점을 바꿔도 Claude를 다시 부르지 않는다.
4. 수정 화면은 서버 **미리보기**로 실제 올라갈 글과 글자 수를 그대로 보여 준다.
5. **디자인 B "옹기"**를 모든 화면에 적용한다.
6. 수정·공유 화면의 사용 방식을 흔히 쓰는 방식으로 바꾼다. 메모는 줄바꿈이 그대로 등록된다.

## 비목표

- 밝은 모드. 어두운 화면 하나만 둔다 (설계자 결정).
- 사진 한도 20장 확장 (보류된 별도 작업).
- 화면 흐름 자체(라우트)의 재구성. 화면 안의 구성과 조작 방식만 바꾼다.
- 이미 저장된 캡션을 이름표 형식으로 옮기는 마이그레이션. 이름표가 없는 기존 캡션은 지금처럼 글자 그대로 쓴다.
- 텔레그램 [상세]·개요 문구 변경. 새 안내 메시지 하나만 더한다.

## 안티 목표

- 되돌리기·다시 하기 기능이 없어지는 것 (사용자 결정: 반드시 유지).
- 수정 화면에 보이는 글(양조장 정보 포함)과 실제로 게시될 글이 다른 것.
- 사용자가 직접 고친 캡션 문장이 저장할 때 몰래 다시 쓰이는 것.
- 웹 담당이 된 게시물의 텔레그램 메시지에 살아 있는 버튼이 남는 것.
- 끌기와 화면 스크롤이 부딪쳐 스크롤하려다 사진 순서가 바뀌는 것.
- 개발용 이름("캡션 머리", "양조장 블록" 등)이 화면에 드러나는 것.
- 랜딩페이지식 장식(그라데이션, 입장 애니메이션, 카드 남발).

## 접근 방식

| 결정 | 고른 것 | 고려한 다른 것 | 이유 |
|---|---|---|---|
| 디자인 방향 | **B. 옹기** (짙은 갈색 바탕, 누룩빛 금색 강조) | A. 청화백자, C. 쪽빛과 새싹 | 사용자 선택. 사진이 가장 돋보인다 |

| 텔레그램 처리 | **버튼 지우고 안내 메시지** | 새 개요 다시 보내기 | 사용자 제안 |

| 미리보기 계산 위치 | **서버 미리보기 API** | 웹에서 이름표 치환 | 도메인 로직은 `apps/api` 한 곳에만 (CLAUDE.md) |

| 작업 나누기 | **브랜치 네 개를 순서대로** | 한 브랜치로 한 번에 | 사용자 선택. 단계마다 리뷰·병합해 위험 범위를 좁힌다 |
| 디자인 토큰 위치 | Tailwind v4 `@theme` (`app/globals.css`) | — | 설계자 결정. 기존 스택, `web.md`(Tailwind만) 준수 |
| 안내 메시지의 웹 링크 | **메시지 안 텍스트 링크** | URL 인라인 버튼 | 설계자 결정. 지금 봇 코드는 콜백 버튼만 지원하고, 텔레그램은 `localhost` URL 버튼을 거부해 개발 환경에서 전송이 실패한다. 메시지 5([수정] 안내)와 같은 방식 |

## 작업 순서 (브랜치)

각 단계는 `dev`에서 딴 피처 브랜치 하나다. 앞 단계를 `dev`에 병합한 뒤 다음 단계를 시작한다. 1·2단계는 지금 자세히 계획한다. 3·4단계는 앞 단계가 끝난 뒤 계획한다(특히 4단계는 화면별 사용성 점검 결과를 사용자에게 보여 준 뒤 계획한다).

1. **양조장 시트와 텔레그램 안내**: 양조장 수정 시 대기 중 캡션 반영, 웹 담당 전환과 텔레그램 안내, 수정 화면의 양조장 칸 제거와 시트.
2. **캡션 이름표와 미리보기**: 이름표 형식, Claude 프롬프트, 저장·게시 시 채우기, 재작성 제거, 미리보기 API.
3. **디자인 기반과 수정·공유 화면**: 토큰·글꼴·공용 부품, 새 사용 방식, 메모 줄바꿈.
4. **나머지 화면**: 기록 목록, 게시물 개요, 양조장 목록·상세·추가, 설정, 로그인, 상단 메뉴.

## 1단계: 양조장 시트와 텔레그램 안내

### 웹: 양조장 시트

- 수정 화면의 양조장 정보 칸 다섯 개(주소·전화·홈페이지·인스타그램·기타 SNS)와 "고치면 다른 게시물에도 반영됩니다" 안내를 지운다.
- 고른 양조장 아래 "양조장 정보 고치기"를 누르면 **아래에서 올라오는 시트**가 열린다. 대상은 지금 화면에 보이는 양조장(새로 고른 양조장 → 새로 고른 술의 양조장 → 저장된 양조장 순)이다.
- 시트 안은 양조장 화면의 폼(`BreweryForm`)을 재사용한다. 시트의 [저장]은 기존 양조장 수정 API로 **양조장만** 바로 저장한다. 시트 위에 "이 양조장을 쓰는 다른 게시물에도 반영돼요"를 짧게 적는다.
- 시트를 닫아도 수정 화면의 입력(술 선택, 사진, 글 등)은 그대로다. 저장 뒤 수정 화면의 양조장 정보(1단계에서는 양조장 블록 표시, 2단계 뒤에는 미리보기)를 새 값으로 다시 불러온다.
- 양조장 정보는 게시물의 되돌리기 기록에 넣지 않는다 (게시물이 아니라 양조장에 바로 저장되는 값이므로).

### API: 게시물 저장의 양조장 처리

- 게시물 저장은 저장 시점에 DB에서 읽은 양조장 값으로 블록을 그린다 (지금 그대로). 그래서 시트에서 고친 값이 다음 게시물 저장에 자연히 들어간다.
- 게시물 수정 요청의 `breweryEdit`는 웹이 더 이상 보내지 않는다. 필드와 처리 코드를 지울지 남길지는 빌더 재량이다. 지우면 관련 검증·테스트도 정리한다.

### API: 양조장을 고치면

양조장 수정이 성공하면 같은 트랜잭션에서:

1. 그 양조장을 쓰는 게시물(게시물 → 술 → 양조장) 가운데 **고칠 수 있는 게시물**(`PostQueryService.editable`: 검토 대기, 또는 인스타그램 컨테이너가 없는 실패)을 찾는다.
2. 각 게시물의 저장된 캡션에서 양조장 블록(마커 사이)만 새 값으로 다시 그린다. 문장과 `captionEdited`는 건드리지 않는다. 기존 `CaptionParts.split` → `join(brewery)` 경로를 재사용한다. 마커가 정확히 2개가 아니면 건너뛴다 (기존 규칙).
3. 캡션이 바뀐 게시물은 버전을 올린다.
4. 그 게시물의 담당이 `TELEGRAM`이면 `WEB`으로 바꾸고 아래 "웹 담당 전환"을 한다.

- 캡션이 없는 게시물(분석 실패)과 이미 게시됐거나 게시 중인 게시물은 건드리지 않는다.
- 다시 그린 캡션이 2,200자를 넘어도 저장한다. 게시 전 기존 길이 검사(`PublishService`)가 막고, 웹이 글자 수를 보여 준다 (설계자 결정, 양조장 저장을 막지 않기 위해).
- 2단계 뒤에는 양조장 값이 이름표로 채워지므로 이 다시 그리기가 필요 없어진다(아래 2단계). 이름표가 없는 기존 캡션을 위해 1단계 처리는 남긴다.

### 웹 담당 전환과 텔레그램 안내

`TELEGRAM` → `WEB` 전환이 일어나는 두 경우(웹 수정 화면 저장, 양조장 수정으로 캡션이 바뀜) 모두 같은 처리를 한다.

- 지금처럼 이전 개요와 실패 알림(메시지 2, 9)의 버튼을 지운다 (`removeOverviewButtons`).
- **새로**: 이전 개요 메시지에 답장으로 안내 메시지를 보낸다. 이전 개요 메시지 id가 없으면 답장 없이 보낸다.

```text
검토와 업로드는 k-drinker에서 이어서 진행해 주세요.
웹에서 열기: {공개 주소}/posts/{id}
```

- 링크는 메시지 5와 같은 HTML `<a href>` 방식이다. 주소는 `app.public-base-url`.
- 중복 키: `handoff:{postId}` (`WEB`은 되돌아가지 않으므로 한 번만).
- `docs/telegram-messages.md`의 "담당 채널" 절, 버튼 제거 규칙, 메시지 목록에 이 메시지를 추가한다. 공통 규칙(느낌표·줄표 없음)을 따른다.

## 2단계: 캡션 이름표와 미리보기

### 이름표

Claude가 캡션을 처음 쓸 때 사실 정보 자리에 이름표를 넣는다. DB에는 이름표가 든 글(틀)을 저장하고, 보여 줄 때와 게시할 때 서버가 현재 값으로 채운다.

| 이름표 | 값 | 출처 |
|---|---|---|
| `{술이름}` | 술 이름 | 게시물의 술 |
| `{술이름태그}` | 술 이름에서 공백·해시태그에 못 쓰는 문자를 뺀 것 (`#{술이름태그}`로 씀) | 게시물의 술 |
| `{종류}` | 탁주·약주·청주·증류주·과실주 등 | 술 |
| `{도수}` | 예: `6%`, `16.5%` (기존 표기: 끝의 0을 뗀 숫자 + `%`) | 술 |
| `{용량}` | 예: `750ml` | 술 |
| `{별점}` | 예: `★4.5` | 게시물 |
| `{양조장}` | 양조장 이름 | 술의 양조장 |
| `{양조장태그}` | 양조장 이름의 해시태그용 형태 | 술의 양조장 |
| `{주소}` `{전화}` `{홈페이지}` `{인스타그램}` `{기타SNS}` | 양조장 연락처. 홈페이지는 `https://` 뺀 글자, 인스타그램은 `@핸들` (기존 양조장 블록 규칙) | 술의 양조장 |

- **양조장 블록도 이름표로 만든다.** 마커 사이를 `🍶 {양조장}` `📍 {주소}` … 줄로 저장하고, 값이 없는 이름표가 든 줄은 통째로 뺀다 (기존 "값이 없는 항목은 줄을 뺀다" 규칙과 같음). 그래서 양조장을 고치면 다시 그릴 필요 없이 다음에 채울 때 자연히 새 값이 들어간다.
- **별점**: 기존 `withRating`(머리 끝 별점 블록 교체) 대신 `{별점}` 줄로 처리한다. 별점이 없으면 그 줄을 뺀다.
- **본문 줄에서 값이 비면**: 이름표가 빈 값이 되는 줄은 그 줄을 뺀다를 기본으로 한다. 본문 문장이 통째로 사라지는 게 어색한 경우가 있으면 빌더가 더 나은 규칙(예: 이름표 주변 구절만 빼기)을 제안할 수 있다. 결과에 빈 줄이 두 번 연속 남지 않게 한다 (기존 규칙).
- **조사**: 한국어 조사는 앞 글자 받침에 따라 바뀐다 (`지평 막걸리는` / `청주는`, `서울장수가` / `화요가`). 이름표 바로 뒤 조사는 `{술이름}은(는)`처럼 쓰게 하고, 서버가 채울 때 받침에 맞춰 하나를 고른다. 대상 조사: 은/는, 이/가, 을/를, 와/과, 으로/로, 이에요/예요. 표기 형식은 빌더 재량이되 Claude 프롬프트와 `docs/instagram-caption.md`에 같은 형식을 적는다.
- **알 수 없는 이름표**(목록에 없는 `{…}`)는 Claude 출력 검증에서 걸러 다시 요청하거나 글자 그대로 둔다 (빌더 재량). 사용자가 글에 직접 쓴 `{…}`도 목록에 있는 것만 이름표로 본다.
- **이름표 없는 기존 캡션**은 그대로 쓴다. 채우기는 이름표가 있을 때만 일어난다.

### 재작성 제거

- 지금 `PostEditService.decideCaption`은 술·양조장이 바뀌고 문장을 고친 적 없으면 Claude로 캡션을 다시 쓴다. 이 경로를 없앤다. 술·양조장·별점을 바꾸면 이름표가 새 값으로 채워질 뿐이다.
- **예외**: 분석에 실패해 캡션이 아예 없는 게시물은 지금처럼 저장할 때 새로 쓴다.
- 이름표가 없는 기존 캡션에서 술을 바꾸면 문장 속 옛 술 이름이 그대로 남는다. 수정 화면이 "이 글은 이름표가 없어 술 이름이 자동으로 바뀌지 않아요"를 보여 준다 (설계자 결정).

### Claude 프롬프트와 문서

- `docs/instagram-caption.md`의 캡션 틀·예시·양조장 블록 절을 이름표 형식으로 고친다. 술 소개 블록의 사실 정보, 해시태그의 술·양조장 태그는 반드시 이름표로 쓰게 한다.
- `ClaudeCaptionWriter` 프롬프트에 이름표 목록·조사 표기·"값이 없는 이름표는 쓰지 말 것"을 넣는다.

### 채우는 곳

- 게시(`PublishWorker`), 웹 개요·상세 응답, 텔레그램 개요·[상세], 글자 수 계산(`CaptionAssembler.length`, 2,200자 검사)은 모두 **채운 글**을 기준으로 한다. 채우는 코드는 한 곳(예: `CaptionAssembler`)에 둔다.
- 수정 화면은 **틀**(이름표가 보이는 글)을 편집하고, 미리보기로 채운 글을 본다.

### 미리보기 API

- 수정 화면의 현재 입력(술 id 또는 새 술 이름, 양조장 id, 별점, 캡션 틀)을 받아 채운 글과 글자 수를 돌려준다. 저장하지 않는다. Claude를 부르지 않는다.
- URL·요청·응답 형식은 `api-conventions` 스킬을 따른다 (예: `POST /api/v1/posts/{id}/caption-preview`).
- 웹은 입력이 잠깐 멈출 때 호출한다(디바운스). 응답이 오기 전에는 이전 미리보기를 흐리게 둔다.

## 3단계: 디자인 기반과 수정·공유 화면

### 디자인 토큰 (B. 옹기)

| 이름 | 값 | 쓰임 |
|---|---|---|
| `bg` | `#1D1713` | 화면 바탕 (옹기 유약) |
| `surface` | `#29211B` | 입력칸·칩·목록 행·시트 |
| `line` | `#3A2F27` | 테두리·구분선 |
| `text` | `#EDE5D8` | 본문 (쌀빛) |
| `muted` | `#A8998A` | 보조 글자·라벨 |
| `accent` | `#D6B04C` | 주 버튼·별점·링크·선택 표시 (누룩빛) |
| `on-accent` | `#1D1713` | 강조색 위 글자 |
| `danger` | 빌더 재량 | 오류·삭제. 어두운 바탕에서 4.5:1 이상 |

- 모든 글자·바탕 조합은 WCAG AA(본문 4.5:1)를 넘긴다. 부족하면 밝기를 조정한다.
- `viewport.themeColor`와 PWA manifest 색도 `bg`로 맞춘다.
- 글꼴: 본문·UI는 **Pretendard**, 술 이름(화면의 주인공 텍스트)에만 **고운바탕(Gowun Batang)**. `next/font`로 자체 호스팅한다.
- 모서리: 입력칸·칩 10px, 썸네일 6px, 주 버튼 알약형. 그림자 대신 `line` 테두리.
- 움직임: 사용자 조작에 대한 반응(끌기, 토스트, 시트)만. `prefers-reduced-motion`이면 끈다.

### 공용 부품 (`components/ui/`)

상단 바(뒤로·제목·오른쪽 동작), 버튼(주·보조·텍스트), 입력칸·여러 줄 입력칸(내용 따라 늘어남), 선택 칩(값 + ×), 토스트(문구 + 동작 하나), 바텀 시트, 확인창(기존 `ConfirmDialog` 재스타일). 변형은 `cva` 또는 유틸 함수로. 이름과 API는 빌더 재량. 1단계의 양조장 시트는 3단계에서 이 부품으로 다시 입힌다.

### 수정 화면 (`/posts/[id]/edit`)

```
┌ ←  수정              ↶  ↷   [저장] ┐  ← 상단 바, 위에 고정
│ 장수 생막걸리  (고운바탕)            │
│ [1 대표][2][3][4][+]                 │  ← 썸네일 가로 줄, 끌어서 순서
│ 술     [ 장수 생막걸리          × ]  │
│ 양조장 [ 서울장수               × ]  │
│        양조장 정보 고치기            │  ← 시트
│ ★★★★☆                               │
│ 메모 (여러 줄)                       │
│ 인스타그램 글  [편집 | 미리보기]     │
│ 1,234자 / 2,200자                    │
└──── 사진을 뺐어요 · 실행 취소 ───────┘
```

**저장**: 상단 바 오른쪽에 고정. 폼 맨 아래 저장 버튼은 없앤다. 저장 중·사진 끌기 중에는 막는다 (기존 잠금 유지).

**되돌리기·다시 하기** (유지, 사용자 결정)
- 상단 바 아이콘 버튼(↶ ↷)으로 옮긴다. 접근성 이름은 "되돌리기"·"다시 하기" 그대로.
- 범위를 **게시물의 모든 입력**으로 넓힌다: 사진(순서·추가·빼기·여백), 별점, 술 선택, 양조장 선택, 메모, 인스타그램 글. 양조장 정보(시트)는 제외 (1단계).
- 글자 입력은 입력이 잠깐 멈출 때마다(예: 1초) 한 번으로 묶는다. 다른 칸으로 옮기면 바로 묶는다.
- 기존 `useUndoable`을 확장한다. 기존 결정(얕은 비교, 저장 중 잠금)은 유지.

**사진**
- 썸네일 가로 줄(4:5 비율). 첫 장에 "대표" 표시.
- 순서: 길게 눌러 끌기(dnd-kit sortable, 터치 지연으로 스크롤과 구분). 키보드로도 옮길 수 있다. [위로]·[아래로] 버튼은 없앤다.
- 빼기: 썸네일 모서리 × 배지. **확인창 없이 바로 빼고** 토스트 "사진을 뺐어요 · 실행 취소". 토스트의 실행 취소는 ↶과 같은 기록을 쓴다. 한 장만 남으면 ×를 숨긴다.
- 여백 넣기·빼기: 썸네일을 누르면 크게 보기(시트나 모달)에서 고른다. 썸네일을 글자 버튼으로 덮지 않는다. 여백 상태는 썸네일에도 보인다.
- 추가: 줄 끝 [+] 타일 (기존 `AddPhotoTile`, 10장 한도 유지).
- 기존 `PhotoOrderList`의 직접 만든 이동 애니메이션은 dnd-kit으로 대체한다.

**술·양조장 검색** (`SearchCombobox`)
- 고른 값은 검색칸 자리에 **칩**(값 + ×). "선택한 양조장: X" 문장은 없앤다.
- 칩이나 ×를 누르면 검색칸으로 바뀌어 바로 입력한다. ×만 누르고 고르지 않으면 술은 선택 없음, 양조장은 술의 기본 양조장 (기존 `picked=null` 의미).
- 검색 결과는 입력칸 아래 **떠 있는 목록**(폼을 밀어내지 않음). 바깥을 누르거나 Esc면 닫힌다.
- 기존 키보드·IME 처리와 combobox ARIA는 유지한다. `DrinkPicker`의 새 이름 등록도 같은 모양.

**메모**: 여러 줄 입력칸, 내용 따라 높이가 는다. 줄바꿈이 그대로 저장된다 (API는 이미 보존, 변경 없음).

**인스타그램 글**
- "캡션 머리 / 양조장 블록 / 캡션 꼬리" 세 칸을 **"인스타그램 글" 하나**로 합쳐 보여 준다. 화면에 개발용 이름을 쓰지 않는다.
- [편집] 탭: 틀을 편집한다. 이름표는 `{술이름}`처럼 보이고, 아래에 이름표 넣기 버튼 줄을 둔다. 양조장 정보 부분(마커 사이)은 편집칸에 보이지 않게 하고 "양조장 정보는 자동으로 채워져요" 한 줄로 대신한다. 마커를 사용자가 지울 수 없게 하는 방법(머리·꼬리 두 칸 유지 + 사이 표시 등)은 빌더 재량이지만 사용자에게는 한 덩어리 글로 보여야 한다.
- [미리보기] 탭: 미리보기 API의 채운 글. 실제 인스타그램처럼 줄바꿈을 지켜 보여 준다.
- 글자 수는 미리보기 API 값으로 입력 중에도 바뀐다. 2,200자를 넘으면 강조색으로 표시하고 저장 전에 보인다.

### 공유 화면 (`/share`)

수정 화면과 같은 사진 썸네일 줄(끌기·× 배지·토스트), 같은 별점, 여러 줄 메모. [보내기] 확인창의 메모 미리보기는 줄바꿈을 보존한다(`whitespace-pre-wrap`). 되돌리기의 위치·범위도 수정 화면과 같게 맞춘다.

## 4단계: 나머지 화면

기록 목록, 게시물 개요, 양조장 목록·상세·추가, 설정, 로그인, 상단 메뉴(`AppNav`)에 토큰과 공용 부품을 적용한다. 화면마다 사용성 점검(`taste-skill:redesign-skill` 감사 방식)을 먼저 하고, 결과를 사용자에게 보여 준 뒤 계획한다. 원칙은 3단계와 같다(흔히 쓰는 방식, 고정된 주 동작, 사진을 글자 버튼으로 덮지 않기, 개발용 이름 숨기기). 라우트는 바꾸지 않는다.

- 게시물 개요의 사진은 실제 게시 비율(4:5)로 보여 준다.

## 제약

- `.claude/rules/web.md`: Tailwind만, 인라인 `style={}` 금지(dnd-kit transform은 예외가 필요할 수 있다. 쓰면 이유를 주석으로), `div onClick` 금지, API 호출은 `lib/api.ts` 래퍼, pnpm.
- 도메인 로직(이름표 채우기, 조사 고르기, 글자 수)은 `apps/api`에만.
- 사진 입력은 `accept="image/jpeg,image/png"` 유지.
- 텔레그램·캡션 문구를 바꾸면 `docs/telegram-messages.md`·`docs/instagram-caption.md`를 함께 고친다.
- API 응답·에러는 `api-conventions` 스킬을 따른다.
- 기존 테스트는 접근성 이름·문구로 요소를 찾는다. 사용 방식이 바뀐 곳(위로/아래로, 삭제 확인창, 양조장 칸, 캡션 세 칸, 재작성)은 테스트를 새 동작에 맞게 다시 쓴다.
- 디자인 작업(3·4단계)에는 사용자가 지정한 스킬을 쓴다: `frontend-design`, `ui-ux-pro-max:design`, `ui-ux-pro-max:brand`, `taste-skill:redesign-skill`, `taste-skill:taste-skill`.
