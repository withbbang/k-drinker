# 텔레그램 메시지 포맷

앱이 보내는 텔레그램 메시지와 버튼 문구를 한곳에 모은 문서다. 문구를 바꾸려면 이 문서와 아래 "소스" 위치를 함께 고친다.

- 상태: 초안 (사용자 점검 대기)
- 설계: `docs/superpowers/specs/2026-11-14-review-to-instagram-design.md`
- 문구 소스: `apps/api/src/main/java/com/kdrinker/telegram/MessageFormatter.java` (P3에서 구현 예정)
- 캡션 규칙: `docs/instagram-caption.md`

## 공통 규칙

| 항목 | 규칙 |
| --- | --- |
| 전송 방식 | Bot API `sendMessage`. 상세는 `sendMediaGroup` + `sendMessage`. 버튼은 인라인 키보드 |
| 서식 | **HTML** (`parse_mode: HTML`). 고정 문구 밖의 값(술 이름, 양조장 이름, 주소, 메모, 캡션, 실패 사유)에 들어간 `<` `>` `&`는 이스케이프한다. 링크는 `<a href="...">` 로 쓴다 |
| 수신자 | 설정된 본인 `chat_id`로만 보낸다. 다른 chat에서 온 메시지와 버튼은 응답 없이 무시한다 |
| 버튼 이름 | 동작 이름 그대로 `[확인]` `[상세]` `[수정]` `[취소]` `[재시도]`. 버튼마다 다른 말을 쓰지 않는다 |
| 버튼 콜백 데이터 | `act:{postId}:{version}`. `act`는 `ok` `detail` `edit` `cancel` `retry` 중 하나. 예: `ok:128:2`. 텔레그램 한도(64바이트) 안이다 |
| 오래된 버튼 | `version`이 현재 게시물 버전과 다르거나 상태가 맞지 않으면 처리하지 않고 팝업으로 알린다. 문구는 "오래된 버튼 문구" 참고 |
| 버튼 제거 | [확인] [취소]를 처리했거나 [수정] 저장으로 새 개요를 보내면 이전 개요 메시지의 버튼을 제거한다 |
| 어조 | 짧고 구체적인 한국어. 상태 알림에는 느낌표를 쓰지 않는다. 줄표 문자(엠 대시, 엔 대시)를 쓰지 않는다 |
| 중복 방지 | 같은 알림을 두 번 보내지 않도록 중복 키를 둔다. 아래 메시지마다 적는다 |
| 실패 처리 | 전송이 실패하면 5초 간격으로 최대 3회 다시 시도한다. 그래도 실패하면 로그만 남기고 게시물 상태는 바꾸지 않는다 |
| 미설정 | `TELEGRAM_BOT_TOKEN` 또는 `TELEGRAM_CHAT_ID`가 비면 보내지 않는다 |
| 이모지 | 개요와 안내에만 쓴다. 쓰는 것은 🍶 📍 🏠 📷 ☎ ⚠ 뿐이다 |
| 별점 표기 | `★4.5` (0.5 단위). 별점이 없으면 `별점 없음` |

## 메시지

### 1. 접수됨 · `RECEIVED`

- **언제:** 사진(앨범)과 메모를 받아 게시물을 만들고(RECEIVED) 분석을 시작한 직후. 웹 공유로 들어온 게시물에도 보낸다
- **중복 키:** `postId`
- **소스:** `MessageFormatter.received(Post)` (P3에서 구현 예정)

템플릿

```text
접수했습니다. 사진 {n}장
분석이 끝나면 개요를 보내 드립니다.
```

예시

```text
접수했습니다. 사진 3장
분석이 끝나면 개요를 보내 드립니다.
```

### 2. 분석 실패 · `ANALYSIS_FAILED`

- **언제:** 분석 단계(ANALYZING)에서 라벨 인식 실패나 Claude 오류로 게시물이 FAILED가 됐을 때
- **중복 키:** `postId:analysisAttempt` (재시도 후 다시 실패하면 새로 보낸다)
- **소스:** `MessageFormatter.analysisFailed(Post)` (P3에서 구현 예정)
- **버튼:** `[재시도]` `[수정]`. [재시도]는 분석 단계부터 다시 실행한다. [수정]은 수정 링크 안내(메시지 5)로 이어진다

템플릿

```text
분석에 실패했습니다.
사유: {실패 사유}
```

예시

```text
분석에 실패했습니다.
사유: 사진에서 술 이름을 읽지 못했습니다.
```

실패 사유 문구 (고정)

| 원인 | 사유 문구 |
| --- | --- |
| 라벨 인식 실패 | 사진에서 술 이름을 읽지 못했습니다. |
| Claude 응답 오류, 시간 초과 | 분석 서버 응답에 문제가 있었습니다. |
| 그 밖의 오류 | 알 수 없는 오류가 났습니다. 서버 로그를 확인해 주세요. |

### 3. 개요 · `PENDING_REVIEW`

- **언제:** 분석을 마치고 PENDING_REVIEW가 됐을 때, 그리고 [수정] 저장으로 PENDING_REVIEW에 다시 들어왔을 때(새 개요)
- **중복 키:** `postId:version` (수정할 때마다 version이 오르므로 새 개요는 새 키)
- **소스:** `MessageFormatter.overview(Post)` (P3에서 구현 예정)
- **버튼:** `[확인]` `[상세]` `[수정]` `[취소]` (한 줄)

양조장을 확인한 경우 (값이 있는 줄만 넣는다)

```text
🍶 게시 대기 · {술 이름} (★{별점})
양조장: {양조장 이름} (출처: {양조장 출처})
📍 <a href="{지도 링크}">{주소}</a> {주소 출처 링크}
🏠 <a href="{홈페이지}">홈페이지</a> {홈페이지 출처 링크}
📷 <a href="https://www.instagram.com/{핸들}/">@{핸들}</a> {인스타그램 출처 링크}
🔗 <a href="{기타 SNS URL}">{기타 SNS 이름}</a> {기타 SNS 출처 링크}
☎ {전화} {전화 출처 링크}
사진 {n}장 · 캡션 {n}자 · 해시태그 {n}개
```

양조장을 못 찾은 경우 (맨 위에 경고, 양조장 줄과 연락처 줄은 넣지 않음)

```text
⚠ 양조장 미확인
🍶 게시 대기 · {술 이름} (★{별점})
양조장 정보 없이 게시됩니다. 캡션의 양조장 블록은 비어 있습니다.
사진 {n}장 · 캡션 {n}자 · 해시태그 {n}개
```

예시 (양조장 확인, 공공데이터 값만 있음. 출처 링크 없음)

```text
🍶 게시 대기 · 화요 25 (★4.5)
양조장: 화요 (출처: 공공데이터)
📍 경기 여주시 가남읍 ...
🏠 홈페이지
📷 @hwayo_official
☎ 031-...
사진 3장 · 캡션 412자 · 해시태그 15개
```

예시 (웹 검색으로 채운 항목에는 줄마다 출처 링크, 기타 SNS 있음)

```text
🍶 게시 대기 · 문배술 (★4.0)
양조장: 문배주양조원 (출처: 웹 검색)
📍 경기 김포시 ... (출처)
🏠 홈페이지 (출처)
📷 @example_brewery (출처)
🔗 블로그 (출처)
☎ 031-...
사진 2장 · 캡션 388자 · 해시태그 14개
```

위 예시에서 `(출처)`는 `<a href="{그 항목의 sourceUrl}">출처</a>`, `홈페이지` `@핸들` `블로그`는 각각 링크다. 전화는 공공데이터 값이라 출처 링크가 없다.

예시 (양조장 미확인, 별점 없음)

```text
⚠ 양조장 미확인
🍶 게시 대기 · 이름 모를 막걸리 (별점 없음)
양조장 정보 없이 게시됩니다. 캡션의 양조장 블록은 비어 있습니다.
사진 1장 · 캡션 205자 · 해시태그 12개
```

- 출처 표기(양조장 줄): `공공데이터`(`PUBLIC_DATA`), `웹 검색`(`WEB_SEARCH`), `직접 입력`(`MANUAL`)
- **항목별 출처 링크 규칙:** 값이 `WEB_SEARCH`로 채워진 항목(주소, 전화, 홈페이지, 인스타그램, 기타 SNS)은 그 줄 끝에 해당 항목의 `sourceUrl`로 가는 `(출처)` 링크를 붙인다. 항목마다 따로 붙인다. `PUBLIC_DATA`와 `MANUAL` 값에는 붙이지 않는다. 출처 URL이 없는 웹 검색 값은 분석 단계에서 버리므로 링크 없는 웹 검색 값은 나오지 않는다
- **SNS는 링크로 쓴다:** 인스타그램 핸들은 `<a href="https://www.instagram.com/{핸들}/">@{핸들}</a>`, 홈페이지는 `<a href="{URL}">홈페이지</a>`. 기타 SNS(`otherSns`)는 항목마다 한 줄로, `🔗 <a href="{URL}">{이름}</a>` 형태로 쓴다 (이름은 블로그 유튜브 등 종류 이름, 모르면 `기타 SNS`)
- 값이 비어 있는 항목은 그 줄을 통째로 뺀다
- 지도 링크: 주소로 만든 네이버 지도 검색 URL (`https://map.naver.com/p/search/{주소를 URL 인코딩}`). P3에서 실제로 열리는지 확인한다
- 캡션 글자 수는 게시 직전 최종 캡션(양조장 블록과 해시태그 포함)을 센다. 2,200자 처리는 `docs/instagram-caption.md`를 따른다
- 캡션이 2,200자를 넘으면 개요 대신 메시지 9의 실패 알림이 간다(게시 전에 감지)
- 술 이름은 사용자가 입력하거나 인식한 이름 그대로 쓴다

### 4. 상세 · `DETAIL`

- **언제:** 개요의 [상세]를 눌렀을 때. 게시물 상태는 바꾸지 않는다. 버튼을 다시 눌러도 보낸다
- **중복 키:** 없음 (누를 때마다 보낸다)
- **소스:** `MessageFormatter.detail(Post)` (P3에서 구현 예정)
- **구성:** (1) 사진 앨범(`sendMediaGroup`, 4:5로 잘린 변환본, 게시 순서. `sendMediaGroup`은 한 번에 최대 10장이고, 게시물도 최대 10장이라 한 번에 보낸다). (2) 캡션 원문 메시지

캡션 원문 메시지 템플릿

```text
캡션 원문 ({n}자)

{캡션 전체}
```

예시

```text
캡션 원문 (412자)

화요 25, 저녁 식탁에 올려 봤어요.
...
#전통주 #우리술 #화요
```

- 캡션 안의 `<!--brewery-->` 마커는 제거해서 보여 준다. 실제로 게시되는 글과 같아야 한다
- 캡션 전체에 HTML 이스케이프를 적용하고 parse_mode는 HTML을 유지한다. 최대 2,200자라 텔레그램 한도(4,096자) 안이다
- 앨범은 사진이 1장이면 `sendPhoto`로 보낸다
- 이 메시지에는 버튼을 붙이지 않는다. 버튼은 개요 메시지에 그대로 남아 있다

### 5. 수정 링크 안내 · `EDIT_LINK`

- **언제:** 개요나 실패 알림의 [수정]을 눌렀을 때
- **중복 키:** 없음 (누를 때마다 보낸다)
- **소스:** `MessageFormatter.editLink(Post, String url)` (P3에서 구현 예정)

템플릿

```text
수정 화면에서 고칠 수 있습니다.
<a href="{수정 화면 URL}">수정하기</a>
저장하면 새 개요를 보내 드립니다.
```

예시

```text
수정 화면에서 고칠 수 있습니다.
수정하기
저장하면 새 개요를 보내 드립니다.
```

- 수정 화면은 웹 로그인이 필요하다. 로그인이 풀려 있으면 로그인 후 같은 화면으로 돌아온다
- 링크를 보낸 뒤에도 게시물 상태는 그대로다. 저장하기 전에는 이전 개요의 버튼이 계속 동작한다
- 저장하면 버전이 오르고 새 개요(메시지 3)가 오며, 이전 개요의 버튼은 제거된다

### 6. 취소됨 · `CANCELED`

- **언제:** 개요의 [취소]를 처리해 CANCELED가 됐을 때. 개요 메시지의 버튼은 제거한다
- **중복 키:** `postId`
- **소스:** `MessageFormatter.canceled(Post)` (P3에서 구현 예정)

템플릿

```text
게시를 취소했습니다. {술 이름}
사진은 7일 뒤에 삭제됩니다.
```

예시

```text
게시를 취소했습니다. 화요 25
사진은 7일 뒤에 삭제됩니다.
```

### 7. 게시 중 · `PUBLISHING`

- **언제:** [확인] 또는 게시 실패 후 [재시도]를 처리해 PUBLISHING이 됐을 때. 개요 메시지의 버튼은 제거한다
- **중복 키:** `postId:publishAttempt` (재시도마다 새로 보낸다)
- **소스:** `MessageFormatter.publishing(Post)` (P3에서 구현 예정)

템플릿

```text
인스타그램에 게시하는 중입니다. {술 이름}
```

예시

```text
인스타그램에 게시하는 중입니다. 화요 25
```

### 8. 게시 완료 · `PUBLISHED`

- **언제:** 인스타그램 게시를 마쳐 PUBLISHED가 됐을 때
- **중복 키:** `postId`
- **소스:** `MessageFormatter.published(Post)` (P3에서 구현 예정)

템플릿

```text
게시했습니다. {술 이름}
<a href="{permalink}">게시물 보기</a>
```

예시

```text
게시했습니다. 화요 25
게시물 보기
```

- `permalink`는 인스타그램이 돌려준 게시물 주소다. 못 가져오면 둘째 줄을 빼고 `게시물 주소를 가져오지 못했습니다. 인스타그램 앱에서 확인해 주세요.`를 넣는다

### 9. 게시 실패 · `PUBLISH_FAILED`

- **언제:** 게시 단계(PUBLISHING)에서 실패해 FAILED가 됐을 때. 또는 게시 직전 검증에서 캡션이 2,200자를 넘은 것이 확인됐을 때(이 경우 PUBLISHING으로 가지 않고 FAILED로 둔다)
- **중복 키:** `postId:publishAttempt`
- **소스:** `MessageFormatter.publishFailed(Post)` (P3에서 구현 예정)
- **버튼:** `[재시도]`. 단 캡션 2,200자 초과로 실패한 경우에는 [재시도]로 해결되지 않으므로 `[수정]`만 붙인다. [재시도]는 게시 단계부터 다시 실행한다. 이미 인스타그램에 올라간 게시물은 다시 올리지 않는다(중복 게시 방지는 API가 처리)

템플릿

```text
게시에 실패했습니다. {술 이름}
사유: {실패 사유}
```

예시

```text
게시에 실패했습니다. 화요 25
사유: 인스타그램이 이미지를 가져가지 못했습니다.
```

실패 사유 문구 (고정, 모르는 오류는 마지막 줄)

| 원인 | 사유 문구 |
| --- | --- |
| 인스타그램이 이미지 URL을 못 가져감 | 인스타그램이 이미지를 가져가지 못했습니다. |
| 토큰 만료, 권한 오류 | 인스타그램 인증에 문제가 있습니다. 토큰을 확인해 주세요. |
| 게시 한도 초과 | 오늘 게시 한도를 넘었습니다. 내일 다시 시도해 주세요. |
| 캡션 2,200자 초과 (게시 전 감지, [수정]만) | 캡션이 2,200자를 넘었습니다. |
| 그 밖의 오류 | 알 수 없는 오류가 났습니다. 서버 로그를 확인해 주세요. |

### 10. 텍스트만 왔을 때 안내 · `TEXT_ONLY`

- **언제:** 사진 없이 텍스트만 온 메시지에 답할 때 (앨범 직후 메모로 붙는 텍스트는 해당하지 않음)
- **중복 키:** 없음 (받을 때마다 보낸다)
- **소스:** `MessageFormatter.textOnly()` (P3에서 구현 예정)

```text
사진이 없어서 게시물을 만들 수 없습니다.
사진을 보내면서 메모를 함께 적어 주세요.
```

- 메모는 사진 캡션에 적거나, 사진(앨범)을 보낸 직후 텍스트로 보내면 된다는 점을 위 문구가 가리킨다. 별도 `/help` 명령은 이번 범위에 없다

### 11. 인스타그램 토큰 갱신 실패 · `TOKEN_REFRESH_FAILED`

- **언제:** 장기 토큰 갱신이 실패했을 때. 만료 7일 전부터는 매일 한 번만 다시 알린다
- **중복 키:** 날짜 (`2026-11-14`)
- **소스:** `MessageFormatter.tokenRefreshFailed(Instant expiresAt)` (P3에서 구현 예정)

템플릿

```text
인스타그램 토큰 갱신에 실패했습니다.
만료 예정: {만료일}({요일})
토큰을 다시 발급해 주세요. 절차는 deploy/README.md에 있습니다.
```

예시

```text
인스타그램 토큰 갱신에 실패했습니다.
만료 예정: 2026-12-02(수)
토큰을 다시 발급해 주세요. 절차는 deploy/README.md에 있습니다.
```

- 재발급한 토큰은 환경변수를 바꾸고 웹 설정 화면의 [토큰 다시 불러오기]로 반영한다. 이 안내는 `deploy/README.md`에 둔다

### 12. 사진 장수 초과 안내 · `TOO_MANY_PHOTOS`

- **언제:** 한 번에 11장 이상(같은 `media_group_id` 앨범이 합쳐서 11장 이상)이 오거나 웹 공유로 11장 이상이 올라왔을 때. 입력은 1~10장까지 받는다(인스타그램 캐러셀 최대 10장). 게시물은 만들지 않고 사진도 저장하지 않는다
- **중복 키:** 없음 (받을 때마다 보낸다)
- **소스:** `MessageFormatter.tooManyPhotos(int count)` (P3에서 구현 예정)

템플릿

```text
사진이 {n}장이라 접수하지 못했습니다.
한 게시물에는 사진을 최대 10장까지 올릴 수 있습니다. 10장 이하로 나누어 다시 보내 주세요.
```

예시

```text
사진이 12장이라 접수하지 못했습니다.
한 게시물에는 사진을 최대 10장까지 올릴 수 있습니다. 10장 이하로 나누어 다시 보내 주세요.
```

## 버튼 클릭 응답 (팝업)

`answerCallbackQuery`로 보여 주는 짧은 문구다. 채팅에 남지 않는다.

### 오래된 버튼 문구

- **언제:** 버튼의 `version`이 현재와 다르거나, 현재 상태에서 받을 수 없는 동작일 때(예: 이미 게시 중인 글의 [확인])
- **소스:** `MessageFormatter.staleButton()` (P3에서 구현 예정)

```text
이미 처리했거나 오래된 버튼입니다. 최신 개요 메시지를 확인해 주세요.
```

### 처리 접수 문구

[확인] [취소] [재시도]를 정상 접수했을 때의 팝업이다. 결과는 위 메시지 6, 7로 이어진다.

| 버튼 | 팝업 |
| --- | --- |
| [확인] | 게시를 시작합니다. |
| [취소] | 취소했습니다. |
| [재시도] | 다시 시도합니다. |
| [상세] | (팝업 없음) |
| [수정] | (팝업 없음) |
